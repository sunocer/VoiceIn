# VoiceIn Windows 部署与 GitHub 发布教程
## 一、普通用户安装

### 环境

- Windows 10/11 x64；
- 可用麦克风和互联网连接；
- 已开通火山引擎大模型流式语音识别；
- 如需 Codex 直接投递：安装 Codex Desktop 和 Node.js；普通输入模式不需要 Node.js。

### 安装步骤

1. 从 GitHub Release 下载 `VoiceIn-0.1.0-alpha-win-x64.exe` 和对应的 `.sha256`。
2. 核对 SHA-256。PowerShell 示例：

   ```powershell
   Get-FileHash .\VoiceIn-0.1.0-alpha-win-x64.exe -Algorithm SHA256
   ```

3. 把 EXE 放到固定目录，例如 `%LOCALAPPDATA%\Programs\VoiceIn\`。不要在设置开机启动后随意移动文件，否则启动项会失效。
4. 双击 EXE。程序在系统托盘常驻，并打开 `http://127.0.0.1:8766/`。
5. 填写火山 AppID + Access Token，或新版 API Key；选择已开通的 Resource ID 后保存。
6. 选择输出目标，把光标放到目标输入位置，按住 F8 说话，松开后等待最终文字。

当前构建没有商业代码签名，Windows 可能显示“未知发布者”。公开发布前建议购买并配置代码签名证书；用户应仅运行自己构建或能核对来源和哈希的文件。

### 快捷键与托盘

- `F8`：按住开始录音，松开结束；
- `Ctrl+Alt+9`：切换“当前聚焦输入框 / Codex 当前任务”；
- 绿色托盘图标：待机；红色：录音；黄色：识别；蓝色：投递；
- 托盘菜单：查看模式、切换目标、打开配置、退出。

切换输出目标只影响下一段录音。普通输入模式不会自动按 Enter。

### 配置与安全

配置文件位于：

`%LOCALAPPDATA%\VoiceIn\config.json`

AppID、Token 和 API Key 使用 Windows 当前用户 DPAPI 加密。密文只能由同一 Windows 用户解密。不要把配置文件提交到 GitHub；虽然是密文，它仍属于用户配置。

本地配置服务只监听 `127.0.0.1:8766`，使用 SameSite 会话 Cookie 和 Origin 检查。识别音频会发送到火山云端。

### 开机启动

首次运行后，程序在以下当前用户注册表位置创建启动项：

`HKCU\Software\Microsoft\Windows\CurrentVersion\Run\VoiceIn`

打包版使用自身 EXE 加 `--background` 参数静默启动。源码版使用 `pythonw.exe` 和 `launcher.pyw`。实际发布前应在干净虚拟机执行一次登录重启测试。

### 卸载

1. 从托盘菜单退出 VoiceIn。
2. 在 Windows“启动应用”中关闭 VoiceIn，或删除上述当前用户启动项。
3. 删除 EXE。
4. 如需同时删除配置，再删除 `%LOCALAPPDATA%\VoiceIn`。该步骤会永久移除已保存的火山凭据和偏好。

## 二、源码开发和构建

### 准备

安装 Python 3.13 x64 和 Node.js，然后在项目根目录运行：

```powershell
python -m pip install -r voicein_windows/requirements-build.txt
.\build_windows.ps1
```

构建脚本会：

1. 执行 Windows 模块测试；
2. 生成应用图标；
3. 使用 PyInstaller one-file/windowed 模式构建 EXE；
4. 生成 SHA-256 文件；
5. 创建不含日志、本机配置和历史测试回执的源码压缩包。

PyInstaller 的 spec 文件负责收集本地网页静态文件和 Codex IPC JavaScript 适配器。one-file 模式运行时会把这些只读资源释放到临时目录；用户配置始终写入 `%LOCALAPPDATA%`，不能写回打包资源。参考 [PyInstaller spec 文件说明](https://pyinstaller.org/en/stable/spec-files.html)。

构建结果：

```text
dist/VoiceIn-0.1.0-alpha-win-x64.exe
dist/VoiceIn-0.1.0-alpha-win-x64.exe.sha256
dist/VoiceIn-0.1.0-alpha-source.zip
```

### 发布前验证

- 在没有 Python 的 Windows x64 虚拟机运行 EXE；
- 保存并重启后确认 DPAPI 配置可读；
- 注销或重启 Windows，确认自动启动且不弹控制台；
- 验证 F8、Ctrl+Alt+9、托盘退出；
- 验证记事本和浏览器输入，不自动按 Enter；
- 安装 Node.js 和 Codex Desktop 后再验证 Codex 模式；
- 使用杀毒软件及 VirusTotal 检查产物；
- 对最终 EXE 进行代码签名，并在签名后重新计算哈希。

## 三、上传 GitHub

### 建立仓库

本目录当前不是 Git 仓库，可在项目根目录执行：

```powershell
git init
git add README.md .gitignore .github voicein_windows VoiceIn-Windows-MVP规格.md VoiceIn.spec build_windows.ps1 docs 启动VoiceIn-Windows.cmd
git commit -m "Initial VoiceIn Windows alpha"
git branch -M main
git remote add origin https://github.com/你的账号/voicein-windows.git
git push -u origin main
```

推送前运行 `git status` 和 `git diff --cached`，确认没有 AppID、Token、API Key、本机用户名、任务 ID、日志或测试对话内容。

### 创建 Release

1. 在 GitHub 仓库打开 **Releases → Draft a new release**；
2. 新建标签 `v0.1.0-alpha`；
3. 上传 EXE 和 `.sha256`；源码 ZIP 可选，因为 GitHub 会为标签自动生成源码归档；
4. 在说明中列出 Alpha 限制、Node.js/Codex 依赖和未签名状态；
5. 先标为 pre-release。

GitHub Release 是基于 Git 标签的可部署版本，并支持附加二进制文件，参考 [GitHub Releases 官方说明](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases)。

### GitHub Actions

仓库包含 `.github/workflows/build-windows.yml`。推送标签 `v*` 或手动运行工作流时，会在 Windows runner 上执行测试并生成构建产物。公开发布前仍需在受控环境完成代码签名；不要把签名证书或密码直接写入仓库。

### 许可证决策

当前没有许可证。上传公开仓库前必须决定：

- 保留所有权：不添加开源许可证；
- 允许宽松复用：评估 MIT/Apache-2.0；
- 要求网络服务修改公开：评估 AGPL-3.0。

许可证会直接影响他人的使用和商业分发权，不应由构建脚本自动选择。
